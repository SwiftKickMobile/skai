## Release 5 — 2026-08-30

- 2026-08-27 **Requirements system added.** New `Guides/Requirements/` holds `requirements-catalog.md` (catalog content rules), `requirements-authoring.md`, `requirements-promotion.md`, and `requirements-artifacts.md`; new `Requirements/` subdirectory documented in `maintain-skai.md`. Adapters install two new skills, `skai-requirements-authoring` and `skai-requirements-promotion`; rerun every installed adapter to pick them up.
- 2026-08-27 **Requirements follow the UI Map change-package model.** Drafts and discussion live in `skai/changes/<change-id>/` (`requirements-authoring.md` plus `proposed-requirements/**`); the canonical catalog at `requirements/**` is written only by promotion, so it carries no discussion items, no `(D#)` citations, and no progress markers of any kind. Mode (baseline vs. scoped change) is inferred from the catalog, never declared by a caller.
- 2026-08-30 **Promotion timing keys on the behavior, not the package's mode.** A package recording behavior that already ships promotes on the human's approval; one recording behavior still to come promotes when the change ships. Keying it to baseline-vs-scoped-change would strand every retro-seeded backfill, which is a scoped change over behavior that shipped before the package was written.
- 2026-08-27 **Requirements catalog conventions defined.** Scopes (`platform` / `domains` / `features` / `apps`), `<folder>/_<folder>.md` indexes, `## PREFIX-NN` heading-per-requirement files, append-only zero-padded IDs with a per-file prefix recorded in its scope index, and a mandatory-cross-reference plus glossary-as-index rule so a catalog stays traversable without reading every file. Projects with an existing `requirements/` tree keep working; the new rules apply to what a package writes, not to what it carries forward. Three repository shapes — `local`, `shared`, `none` — describing where a repo's catalog lives. Every shape has exactly one catalog, so IDs are always bare; a mixed local/shared shape is deliberately not supported until there is a real case for it.
- 2026-08-27 **Integration doc gains a `requirements` managed section.** New `Templates/docs/skai/integration-sections/requirements.md` records a project's repository shape (`local` / `shared` / `none`) and the catalog root. `Install/integration-doc-install-update.md` now installs it on every project — it is not stack-dependent — so all three adapter runbooks pick it up with no changes of their own. Rerun adapters to add the block; fill its 🟡 values or requirements workflows will block.
- 2026-08-27 **Work-spec creation no longer writes requirements.** Its normalization step now hands the planning document's behaviors to requirements authoring instead of writing `/requirements/**`. The "Requirements Repository Organization" and "Canonical requirements writing style" sections moved out to `Guides/Requirements/requirements-catalog.md`; the Requirements Inventory may now cite not-yet-promoted IDs, marked `(pending)`. Under repository shape `none` the normalization step and its gate are skipped rather than handed off, since authoring's `none` stop is terminal and would not return. `work-spec-implementation.md` and `dev-retro.md` now name the catalog by the Integration block's root rather than a literal path, which is wrong under `shared`.
- 2026-08-27 **Dev retro seeds a requirements package instead of writing the catalog.** Step 5's detection is unchanged, but findings land in `skai/changes/<change-id>/` with unsettled points as `- [ ] D<n>` items, and retro stops at a new requirements handoff gate ahead of the existing process-improvement one. Retro Inputs now include open change packages so it does not re-raise pending findings. Rerun adapters to refresh the `skai-dev-retro` wrapper, whose description changed.

## Release 3 — 2026-08-29

- 2026-08-29 **`skill-refinement` is now `refinement` — renamed asset, id, and vocabulary.** `Guides/Process/skill-refinement-guide.md` → `Guides/Process/refinement-guide.md`; manifest id `guide.skill-refinement` → `guide.refinement`; title "Skill Refinement Guide" → "Refinement Guide". The method never refined a skill — it refines the guide document(s) that tell an agent how to carry out a process — so throughout both guides "the skill under review" is now **the refinement target**, `<skill-name>-refinement.md` is `<target-name>-refinement.md`, and the design spec belongs to the target. In `cold-review-prompt-template.md` the slot `{{SKILL_NAME}}` is now `{{TARGET_NAME}}`. No behavior change.
- 2026-08-29 **Round scoring added.** `refinement-guide.md` gains § *Round score* at the end of *Iterated review*: `score = Σ over new live findings in the binding review target of consequence × reachability × verification`, with the weights (irreversible 20 · divergent 5 · cosmetic 2; normal ×1.0 · off-normal ×0.75 · past-a-rule ×0.25; verified ×1.0 · speculative ×0.5), a noise count, a per-round results table with a worked derivation, and the limits — it never decides when to stop, and a new series starts when the effort, factor table, binding target, or report charter changes. Every round is scored, starting with the first commissioned. Label definitions live only in the template.
- 2026-08-29 **Score distinct defects, not reported findings.** `refinement-guide.md` § *Finding matrix* is now one row per defect: several reported findings that are one defect collapse into one row, and that row copies the **whole label set of its heaviest constituent finding** (largest consequence × reachability × verification, tie-broken by report order) — never the strongest value on each axis separately, which would build a row no reviewer reported and can turn two findings worth 5 into one worth 20. A finding restating a defect already in the findings log is that defect: a standing disposition makes the row noise, a closure shown to be reproducing is live again and scores. Every reported finding keeps its mapping to a row. § *Round score* sums matrix rows, and counts noise in rows too. Without this the score tracked how finely a reviewer chose to split its report rather than what was wrong.
- 2026-08-29 **`irreversible` and `normal` sharpened after reviewer interviews.** In `cold-review-prompt-template.md`: `irreversible` is now "destroys work, or leaves the effort's own records unrecoverable or not comparable", with an explicit carve-out that ambiguity leaving the inputs auditable is `divergent`; `normal` is "the main path — a step taken on every round counts, even when it usually resolves to nothing"; `off-normal` is "a branch reached only when a triggering event occurs". Two reviewers scoring identical text disagreed by 4x on one label and by 1.33x on another; interviewing both traced it to these two phrases, and re-testing them against the new wording produced identical labels, both reported as forced rather than judged. **This changes the factor definitions, so an in-flight effort starts a new score series at the next round.**
- 2026-08-29 **Cold-review output contract changed — reviewers state facts, not grades.** `cold-review-prompt-template.md` § *Output*: two new required per-finding fields, **Consequence** (`irreversible` / `divergent` / `cosmetic`) and **Reachability** (`past-a-rule` / `normal` / `off-normal`), each with a first-match-wins test order; `verified` / `speculative` now defined identically in the Output section and the tooling-verification paragraph (`verified` = ran the command or read the implementation, not merely read the reviewed documents); and **"ordered by severity" and "Top" were removed** from the Output instruction, since ranking requires computing the grade the design removes. Appendix findings must keep the three facts. Re-fill in-flight prompts from the updated block.
- 2026-08-29 **Coverage map is now the findings log, and it is committed.** Renamed throughout both guides and moved to `skai/refinement-reviews/<target-name>-findings.md` — one per target, no branch or session in the path. It was `skai/working-docs/<branch-path>/<session-name>/<skill-name>-coverage.md`, which the installers' `.gitignore` block excludes, so the cross-pass record never survived a clone and a later pass could not find it. Its dispositions must now be appended each round, not only at pass close, because the score's noise rule reads them.
- 2026-08-29 **Triage `reject` sharpened.** In `refinement-guide.md`, `reject` now means the finding fails to establish a live defect, and states that reasoning from the documents rather than from running something is *not* grounds to reject — that is the reviewer's `speculative` evidence mark. `human decision` now reads "a live defect whose fix adds process weight" rather than "may be valid". Previously a literal refiner could reject every document-only finding.
- 2026-08-29 **Retro's `## Gates` check narrowed to gated workflows.** `maintain-retro.md` § 5 previously required a `## Gates` section of any guide "containing STOP points/gates", which false-positived on method guides whose STOPs are internal steps. It now keys on whether the agent waits on the human and emits `⏳ GATE:` lines.

**Migration:**
1. Asset renamed: `Guides/Process/skill-refinement-guide.md` → `Guides/Process/refinement-guide.md`, id `guide.skill-refinement` → `guide.refinement`. Remove the old installed file and install the new one; a host that only refreshes by id will otherwise keep a stale copy.
2. Move any existing coverage map: `skai/working-docs/<branch-path>/<session-name>/<skill>-coverage.md` → `skai/refinement-reviews/<target>-findings.md`, and commit it. `skai/refinement-reviews/` is tracked by default; no ignore-block change.
3. `Managed-Updated-At` bumped to 2026-08-29 on `guide.refinement`, `guide.cold-review-prompt-template`, and `guide.maintain-retro`. Re-run installed adapters to refresh those managed files.

## Release 2 — 2026-08-28

- 2026-08-13 **Cold-review template gains optional scoped/empirical-review slots.** Four new delete-if-inapplicable sections in `Guides/Process/cold-review-prompt-template.md`: `{{EXCLUDED_SURFACES}}` (files the reviewer must not read — blindness fence), `{{OBSERVED_FAILURES}}` (behavioral failure evidence, treated as part of the standard, with an answer-baking guard), `{{PROPOSED_EDITS}}` (draft edits to assess), and `{{REPORT_CHARTER}}` (scoped main report; out-of-charter findings go to an appendix). `Guides/Process/skill-refinement-guide.md` now notes findings may come from an empirical failure sweep via those slots. - 2026-08-14 **Codification bar scoped to codification.** `Guides/Process/skill-refinement-guide.md`'s codification check (step 2) and recurrence threshold now state they gate rule-minting from incidental observations — not repairing deterministic document defects on first sight, nor sharpening an existing rule against a scoped review's chartered empirical failure. Content-only sharpening; no paths, ids, or re-runs.
- 2026-08-15 **Anti-over-engineering triage bar added.** `Guides/Process/skill-refinement-guide.md`: the codification check's log-only step now also covers strand-class findings — when the workflow has a designed escalation route, a gap that merely strands the operator is `log only` regardless of severity until it actually occurs; repair-at-any-likelihood is reserved for text that teaches a wrong action. `Guides/Process/cold-review-prompt-template.md` carries the reviewer-facing statement ("Stranded is not broken") so cold reviewers self-triage such findings. - 2026-08-15 **Refinement supports declared size budgets.** `Guides/Process/skill-refinement-guide.md` gains one conditional paragraph (§ Repairing, "Size budgets"): when a skill's design spec declares a size budget for its guides, repairs state their net size cost, short headroom pairs additions with compensating trims (trims ride normal verification), a can't-fit fix routes to `human decision`, and closure records the guide set's net size change. Inert for skills without a declared budget. Content-only; no paths, ids, or re-runs.

**Migration:** none. All four entries are content-only — no assets added, moved, or renamed; no ids, managed blocks, or managed headers changed; nothing to re-run. Hosts pick these up on a normal guide refresh.
