# Release 12 — 2026-10-13

**Installation**

- 2026-10-12 **New components are offered, never silently skipped.** A component a host has never seen (in the manifest, eligible, not in `skai/config.json`, not in the adapter's component history) is `newComponents` in the resolver's output. On a configured host the update stops at a new-components gate: `next` opens the configure app, which lists them first in a **New** section until Save; an inline answer is written through the configuration tool's new `--enable` / `--decline` flags, which append to the project config or record a declined history entry, so the agent never edits config JSON. Under `auto`, new components are enabled and named at completion; a default host installs them as before and names them too. Declined components start the component ledger like any removal. The bundled app (rebuilt) and `Bin/skai-configuration.py` both return `newComponents` and accept `--enable` / `--decline` (with optional `--target-sha` and `--date`); the app lists new components first, checked, under **New 🔥 — configure to use** until Save, and Save stays available while any are listed. **Hosts:** no migration; the behaviour applies from the next update.
- 2026-10-12 **Configure SKAI window rewritten in SwiftUI.** Same behaviour and JSON events; categories are now collapsible (collapsed by default, chevron in the margin, animated), the list grows downward without moving the row under the pointer, and Save and Apply takes a click (no Return binding). The window's logic lives in `internal/apps/ConfigureSKAI/ConfigureModel.swift` with native tests. The app icon is now an Icon Composer file (`internal/branding/SKAIConfigure.icon`), compiled by `actool` into `Assets.car` with an ICNS fallback, so the system draws the standard shape. **Hosts:** nothing to do; the app is read from the SKAI checkout.

**Design**

- 2026-10-12 **Figma designer guide, rewritten as platform-agnostic conventions.** `Guides/Design/designer-guide.md` → `Guides/Design/figma-designer-guide.md` (Managed-Id `guide.designer-guide` unchanged; it is Figma-specific, so the name says so). The guide now holds for any front end, web included: it names no device, platform UI or screen size. The `Conventions` frame records the designer's choices — target sizes (orientation included), platforms and the one whose look screens use, dark mode, button case, UI kits. New or changed rules: states are chosen for the screen (control states in component sets, changes inside a component in its `<Component> Reference` frame, overlays as screen states); a `Platforms` Section shows once how shared chrome differs on other platforms; kit components are used linked and wrapped to customize; spacing, radii and font sizes bind `spacing/`, `radius/` and `type/` variables on one scale (1–4, then steps of 5; steps of 10 preferred from 30 up) in a `Dimensions` collection and Section; frames are never rotated; canvas measurements are in px; an agent that cannot load a style's font stops and asks, never works around it; a *Working a backfill* section says to draw what the product shows, not how it is built, and to log defects rather than reproduce them; an *Agent tooling* section lists reusable Figma MCP practices. Removed: the `<Feature> Concepts` and `Archive` pages, the `legacy` dormant-design rule, the `Component:` crop naming, the custom-font stand-in procedure, and the PDF-conversion practice. A change page named for its change package holds drafts until they are on `Production`. Companion `figma-designer-guide-multiple-sizes.md` covers files with more than one target size (a `Dimensions` mode per size, `-adapt` variables only where values differ, screens as components with instances per size, chrome switched by a `target` variable); single-size files never read it. Standard and size budget: `skai/refinement-reviews/figma-designer-guide-design.md`. **Migration:** repoint references to the old guide path (README resources tables, project docs). The addendum lookup name follows the rename: if `skai/addenda/designer-guide-addendum.md` exists, move it unchanged to `skai/addenda/figma-designer-guide-addendum.md`. Existing Figma files are not migrated; when next reworked, record target sizes and platforms in `Conventions`, adopt the `Dimensions` variables, delete or fold in `Concepts` and `Archive` pages, and move `Component:` crops into their component set or Reference frame.
- 2026-10-12 **Design authoring and promotion.** Two tool-agnostic process guides, `Guides/Design/design-authoring.md` and `design-promotion.md`, parallel to requirements, with skills `skai-design-authoring` and `skai-design-promotion` (manifest category `Design`). A change package at `skai/changes/<change-id>/design/` holds `design-authoring.md` and `design-promotion.md`; the drafts live on a change page named `<change-id>` in the design file. Authoring alternates discussion and mockup phases — nothing is drawn while items are open, and feedback on mockups goes into the designs or opens the next discussion — and ends with a Design Changes inventory after approval. Promotion screens readiness, checks the drafts against the tool guide and the inventory against the page, refactors production to absorb the page, stops for the supervisor to review production, then deletes the page and archives the package to `skai/promoted/<change-id>/design/`. Each process guide loads the conventions guide for the project's design tool (`figma-designer-guide.md` for Figma), as UI Map implementation loads its stack guide. Implementing designs in code is out of scope. All four Design guides carry the Project addendum boilerplate (`skai/addenda/<guide-name>-addendum.md`). Standard and size budgets: `skai/refinement-reviews/design-process-design.md`. **Installation:** re-run the installation update to install the two skills.

**Guide addenda**

- 2026-10-13 **New addendum report lines.** Before using a guide, the agent now reports `- 📖 SKAI guide: <lookup-name>`, with a nested `- 📎 Addendum loaded` only when an addendum was loaded; a guide line alone means the project has no addendum for it. A failed lookup nests `- ⛔ Addendum lookup failed: <what failed>` and stops. Each guide is reported once per task. This replaces `📎 ADDENDUM: <filename> — loaded` and `No project addendum found: <filename>.`; only each guide's Project addendum footer changed. No migration: lookup names, addendum paths and installed files are unchanged.

**UI Map renderer**

- 2026-10-13 **Visual-home loops are an error.** A map whose visual homes form a loop (for example a `primary_parent` the scene itself routes to) used to render without error while silently dropping the looped scenes. `Bin/ui-map-render.py` now aborts with a `UI Map error` listing the scenes it can't place. Maps that rendered correctly before render identically. Migration: none for maps that render today. If an existing map now fails with this error, its render was already missing those scenes; give one listed scene a `primary_parent` outside the loop and re-render.
