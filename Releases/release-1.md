# Release 1 — 2026-08-12

- 2026-05-27 **Workflow progress and discussion artifacts now use checkboxes.** Managed process artifacts use stable letter-led `- [ ]` / `- [x]` items, while `🟡` is reserved for in-code TODO markers. Spec, test, debugging, retro, process-improvement, and ticket workflows adopt the shared discussion-item and gate-persistence conventions; rerun installed adapters to refresh managed guides and skill wrappers.
- 2026-06-03 **Project-owned SKAI artifacts moved to top-level `skai/`.** Migrate `docs/skai/integration.md` → `skai/integration.md`, `docs/skai/install-state.json` → `skai/install-state.json`, `docs/skai/ui-map/` → `skai/ui-map/`, `docs/skai/changes/` → `skai/changes/`, and `working-docs/` → `skai/working-docs/`. Updated adapter runbooks plan these moves explicitly, stop on destination collisions, and update the managed ignore block to `skai/working-docs/`; rerun every installed adapter.
- 2026-06-03 **UI Map split into architecture and implementation.** Adapters now install `skai-ui-map-architecture` plus the updated implementation skill and refresh `skai-ui-map-planning` as a deprecated compatibility router. Architecture writes `skai/changes/<change-id>/ui-map-architecture.md`, `proposed-ui-map.yaml`, and `proposed-ui-map.svg` while the official map remains frozen; implementation audits code, owns checkbox-tracked code changes, raises approved change requests, and performs terminal promotion.
- 2026-06-11 **Installation updates now target numbered releases.** `skai-update-installation` defaults to the highest `v<N>` tag, reports intervening `## Release <N>` sections, and records `lastRelease` in `skai/install-state.json`; branch-head and commit targets remain explicit overrides. The updater can read the legacy state path long enough for adapter migration to move it.
- 2026-08-05 **Cold review and skill refinement were hardened.** Cold reviews declare scope and settled dispositions, recommend fixes with bloat/churn triage, and verify tooling claims against implementation while leaving command syntax to mechanical checks. Refinement adds lightweight/structured/full tiers, original-agent postmortems when available, repair self-verification, rule-impact tracking, and a terminal clean review or human-ratified unimplemented ledger.
- 2026-08-11 **UI Map artifacts, validation, and implementation semantics were tightened.** New architecture/implementation artifact references define stable `M#` and `T#` ownership, completion checkboxes, and `implement | placeholder | planned | handoff` dispositions. Modal destinations now require an agreed `modal_style` from the map vocabulary, renderer validation enforces it, implementation must use it, Build evidence is append-only per invocation, and source operations remain separate from independent audit deviations.
- 2026-08-11 **UI Map placeholder support was aligned with rendered architecture.** `SKAISwiftUI` domain colors follow map declaration order, only embedded composite content receives inset treatment, and platform placeholder guides define package/linkage, route, breadcrumb, dismiss, and missing-mapping behavior. Build adds the local package only when absent; Plan records owned work without changing app/project code.
- 2026-08-11 **Integration commands preserve the real tool exit status.** Xcode, Swift Package, and Gradle command templates enable `set -o pipefail` before pipelines using `tee`, so captured evidence cannot turn a failed build or test into shell exit 0. Rerun adapters to refresh managed integration blocks.
