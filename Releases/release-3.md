# Release 3 — 2026-08-29

- 2026-08-29 **`skill-refinement` is now `refinement` — renamed asset, id, and vocabulary.** `Guides/Process/skill-refinement-guide.md` → `Guides/Process/refinement-guide.md`; manifest id `guide.skill-refinement` → `guide.refinement`; title "Skill Refinement Guide" → "Refinement Guide". The method never refined a skill — it refines the guide document(s) that tell an agent how to carry out a process — so throughout both guides "the skill under review" is now **the refinement target**, `<skill-name>-refinement.md` is `<target-name>-refinement.md`, and the design spec belongs to the target. In `cold-review-prompt-template.md` the slot `{{SKILL_NAME}}` is now `{{TARGET_NAME}}`. No behavior change.
- 2026-08-29 **Round scoring added.** `refinement-guide.md` gains § *Round score* at the end of *Iterated review*: `score = Σ over new live findings in the binding review target of consequence × reachability × verification`, with the weights (irreversible 20 · divergent 5 · cosmetic 2; normal ×1.0 · off-normal ×0.75 · past-a-rule ×0.25; verified ×1.0 · speculative ×0.5), a noise count, a per-round results table with a worked derivation, and the limits — it never decides when to stop, and a new series starts when the effort, factor table, binding target, or report charter changes. Every round is scored, starting with the first commissioned. Label definitions live only in the template.
- 2026-08-29 **Score distinct defects, not reported findings.** `refinement-guide.md` § *Finding matrix* is now one row per defect: several reported findings that are one defect collapse into one row, and that row copies the **whole label set of its heaviest constituent finding** (largest consequence × reachability × verification, tie-broken by report order) — never the strongest value on each axis separately, which would build a row no reviewer reported and can turn two findings worth 5 into one worth 20. A finding restating a defect already in the findings log is that defect: a standing disposition makes the row noise, a closure shown to be reproducing is live again and scores. Every reported finding keeps its mapping to a row. § *Round score* sums matrix rows, and counts noise in rows too. Without this the score tracked how finely a reviewer chose to split its report rather than what was wrong.
- 2026-08-29 **`irreversible` and `normal` sharpened after reviewer interviews.** In `cold-review-prompt-template.md`: `irreversible` is now "destroys work, or leaves the effort's own records unrecoverable or not comparable", with an explicit carve-out that ambiguity leaving the inputs auditable is `divergent`; `normal` is "the main path — a step taken on every round counts, even when it usually resolves to nothing"; `off-normal` is "a branch reached only when a triggering event occurs". Two reviewers scoring identical text disagreed by 4x on one label and by 1.33x on another; interviewing both traced it to these two phrases, and re-testing them against the new wording produced identical labels, both reported as forced rather than judged. **This changes the factor definitions, so an in-flight effort starts a new score series at the next round.**
- 2026-08-29 **Cold-review output contract changed — reviewers state facts, not grades.** `cold-review-prompt-template.md` § *Output*: two new required per-finding fields, **Consequence** (`irreversible` / `divergent` / `cosmetic`) and **Reachability** (`past-a-rule` / `normal` / `off-normal`), each with a first-match-wins test order; `verified` / `speculative` now defined identically in the Output section and the tooling-verification paragraph (`verified` = ran the command or read the implementation, not merely read the reviewed documents); and **"ordered by severity" and "Top" were removed** from the Output instruction, since ranking requires computing the grade the design removes. Appendix findings must keep the three facts. Re-fill in-flight prompts from the updated block.
- 2026-08-29 **Coverage map is now the findings log, and it is committed.** Renamed throughout both guides and moved to `skai/refinement-reviews/<target-name>-findings.md` — one per target, no branch or session in the path. It was `skai/working-docs/<branch-path>/<session-name>/<skill-name>-coverage.md`, which the installers' `.gitignore` block excludes, so the cross-pass record never survived a clone and a later pass could not find it. Its dispositions must now be appended each round, not only at pass close, because the score's noise rule reads them.
- 2026-08-29 **Triage `reject` sharpened.** In `refinement-guide.md`, `reject` now means the finding fails to establish a live defect, and states that reasoning from the documents rather than from running something is *not* grounds to reject — that is the reviewer's `speculative` evidence mark. `human decision` now reads "a live defect whose fix adds process weight" rather than "may be valid". Previously a literal refiner could reject every document-only finding.
- 2026-08-29 **Retro's `## Gates` check narrowed to gated workflows.** `maintain-retro.md` § 5 previously required a `## Gates` section of any guide "containing STOP points/gates", which false-positived on method guides whose STOPs are internal steps. It now keys on whether the agent waits on the human and emits `⏳ GATE:` lines.
