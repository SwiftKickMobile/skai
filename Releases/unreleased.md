# Unreleased

**Spec tool**

- 2026-10-18 **`check-changes` matches entries by kind.** A change-list entry names only things of its own type: a glossary entry, an index line, a file or folder, or an item. A glossary term, an index line and a section sharing a name (`Appointment`, the `appointment` index line, an `## Attention` section beside the `attention` term) no longer collide. **Migration:** none.
- 2026-10-18 **`render` and `check-changes` take `--base DIR`** (repeatable): further base roots layered over the catalog, each later one winning, so a package can be drafted on top of another open package's drafts and diff against them, the way `validate` already projects several roots. **Migration:** none.
- 2026-10-19 **`link-terms` leaves a term alone inside a longer term's link.** A match anywhere inside a glossary link's label counts as linked, so `[Appointments stage][g-appointments-stage]` no longer gets `appointment` wrapped again on the next run. **Migration:** none; a draft that already carries the nested form reads correctly once the inner link is removed by hand.
- 2026-10-19 **The review page links artifact prose.** Discussion items, Situations, change-item justifications and a request's head get the same chips and dotted terms as spec prose: a bare requirement ID and every glossary term are linked at render time, with popovers, outside existing links and code; the artifact file is not edited. Render convention 8. **Migration:** none; re-render open packages to pick it up.

**Change request triage**

- 2026-10-19 **The supervisor rules on change requests; the agent applies the ruling.** `Guides/ProductSpecs/product-specs-{authoring,artifacts,promotion}.md`, `Guides/DesignSpecs/design-specs-{authoring,artifacts,promotion}.md`, `design-specs.md`, `Guides/UIMap/ui-map-architecture{,-artifacts}.md`, `Guides/Design/design-{authoring,promotion}.md`: a request's status moves only on the supervisor's instruction (`Incorporated` once drafts and the change list reflect it; `Rejected` / `Superseded` with the supervisor's reason), the agent leaves a `Proposed` request alone until told and never rejects or supersedes on its own; a change request exists only against an open package (the "against the catalog, which opens a new package" path is gone — with no package open, whoever finds the defect opens one through authoring); supervisor input during authoring is a decision, recorded as a checked Discussion item when it arrives without one. Promotion's own requests are filed inside the package being promoted; readiness condition 5 exempts only those and still holds at the write; design promotion returns to authoring when a ruling invalidates the approved mockups; design authoring keeps every filed request listed with its status through promotion. Standard: `skai/refinement-reviews/product-specs-system-design.md` § Decisions — 2026-10-19; log `change-request-triage-findings.md`. **Migration:** none for files; an open package holding a request filed "against the catalog" is reopened as an ordinary authoring package with the request as an Input.
- 2026-10-19 **The package card no longer claims promotion readiness.** `render`'s card state reads `discussion complete` when every Discussion item is resolved (`N open` and `no discussion items` unchanged); whether a package may promote is promotion's readiness screen, which also looks at change requests. **Migration:** none; re-render to pick it up.
- 2026-10-19 **Discussion items are collapsible on the review page.** Each item is a card whose summary line shows the square (green resolved, amber open), ID, kind, title and the word "open" or "resolved"; resolved items start collapsed, open ones expanded. **Migration:** none; re-render to pick it up.
