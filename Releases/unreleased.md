# Unreleased

**Figma designer guides**

- 2026-11-19 **The structure check no longer stops on grouped layers or mixed values** (`Bin/figma-page-check.js` `has`, `above0`; `internal/tests/tools/figma-page-check/test.py`): on a real design file the check stopped with a TypeError, because Figma throws when a node is asked for a property its type lacks (a group has no text ranges) and a corner radius or spacing that differs across a node's parts is `figma.mixed`, which no number comparison accepts. Each read is now tested first and only numbers are compared, so a mixed value is not reported; a numeric corner beside it still is. The test's stand-in for Figma throws on a missing property for a node marked strict and supports a mixed value. **Migration:** none; run the check again where it stopped.

**Spec tools**

- 2026-11-25 **Item ID prefixes may hold digits** (`Bin/spec-tool.py` `ID_RE`; `Guides/Core/spec-file-shape.md`; `internal/tests/tools/spec-tool/`): a prefix was letters and hyphens only, so `convert` and `validate` read an item such as `A11Y-01` as a plain section and passed the file with none of its items checked. Each hyphen-separated part now starts with a letter and may hold digits; a one-character prefix is still not an ID. **Migration:**
  1. Discover: search each spec catalog and each open package's drafts for prefixes holding a digit, `grep -rnE '^##+ [A-Z][A-Z0-9-]*[0-9][A-Z0-9-]*-[0-9]{2,}( \(retired\))?$' <root>`, reading `<root>` as the production artifacts root's spec folders and the change packages folder. None: nothing to do. Promoted packages stay as they are.
  2. A file still in the old shape (`## A11Y-01` headings) whose folder was already converted by the Release 14 step may carry glossary links the conversion added around or inside the items it did not recognize. Where the pre-conversion text is available (git, or the update's baseline copy), restore that file from it, keeping any edit made since; show the supervisor when there is such an edit.
  3. Run `python3 Submodules/skai/Bin/spec-tool.py convert <catalog>` (with each open package's drafts as their own root, after the catalog), then read the diff: a file that was already converted should not change, but the conversion wraps a link repaired by hand again when its label is a glossary term (skai#114); undo those.
  4. Verify: `validate` reports no "must not carry an ID" for these files, every item keeps its ID and wording, and the citations in the file resolve. Render each open package that holds such a file again.
- 2026-11-25 **Links to headings resolve as GitHub anchors them** (`Bin/spec-tool.py` `heading_anchors`; `internal/tests/tools/spec-tool/test.py`): the validator collapsed a run of punctuation and spaces to one hyphen, so it rejected a working link to a heading such as `ISSUE-02 — Reminders repeat` (`#issue-02--reminders-repeat`). A link may now name a heading by GitHub's anchor or by the one review pages give it. **Migration:** none; a link changed only to satisfy the validator still resolves there, and can be put back to GitHub's anchor where it stopped working on GitHub.
- 2026-11-25 **The spec, design and UI Map tools run on the Python versions they declare** (`Bin/spec-tool.py` `retired_badge`; `internal/tests/tools/spec-tool/test.py`): two lines of `spec-tool.py` needed Python 3.12, so it stopped with a SyntaxError on 3.9 to 3.11, and `design-tool.py` and `ui-map-render.py`, which import it, stopped with it. Pages are unchanged. Every script under `Bin/` was checked; a test now rejects such a line in any of them. **Migration:** none; run the command again where it stopped.
- 2026-11-25 **A link labeled with a file's name is not a use of a glossary term** (`Bin/spec-tool.py` `FILE_LINK_RE`, `unlinked_uses`, `validate`; `internal/tests/tools/spec-tool/test.py`): a link to a whole spec file whose label held a glossary term failed `validate`, and `link-terms` and `convert` wrapped the term inside it (`[[reminders][g-reminder]]`). A label that is the file's name with its extension, `[reminders.md]: reminders.md`, or the end of its path where the name alone is not enough, `[domains/reminders.md]`, is now left alone; `validate` reports one in a spec file that points at another file or at an anchor. Other labels work as before; where file links belong and what their labels must be is skai#160. **Migration:** optional; where `validate` reports an unlinked term inside a file link's label, relabel the link and its definition with the file's name. Undo a term link an earlier run wrapped inside such a label (`[[`) first. `validate` then reports neither, and `link-terms` leaves the file unchanged.
- 2026-11-25 **A term inside a longer term is no longer linked on its own** (`Bin/spec-tool.py` `unlinked_uses`, `validate`, `link_terms`; `internal/tests/tools/spec-tool/test.py`): `link-terms` and `convert` took terms in glossary order, so with both "Reminder" and "Reminder log" in the glossary they wrote `[reminder][g-reminder] log`, and `validate` passed it. The longest term now wins, and in an item governing the longer term its words are not linked as the shorter one. `validate` reports a term only some of whose words are linked, and `link-terms` replaces those links with one on the whole term, dropping a definition nothing uses any more. A term broken across two lines is still not seen. **Migration:**
  1. Discover: run `python3 Submodules/skai/Bin/spec-tool.py validate` on each spec catalog and on each open package projected. Lines ending "only some of its words are linked" are these; none: nothing to do. Promoted packages stay as they are.
  2. Transform: run `link-terms <catalog>`, then `link-terms <catalog> <drafts>` per open package, and read the diff: only links change, never wording; undo any other line it wrapped (skai#114).
  3. Verify: `validate` reports none, and a second `link-terms` changes nothing. Render each changed open package again.
